# CLAUDE.md

Правила для AI-сесій у цьому репозиторії. Що вміє застосунок — `README.md`,
як його розгорнути — `docs/SETUP.md`. Тут лише те, що треба знати, перш ніж
міняти код.

## Власник

Taskly — особистий застосунок одного власника (Taison), не продукт для
сторонніх. Власник не розробник: пояснюй простими словами, що змінено і що
від нього потрібно, без простирадл коду. Спілкування українською.

Назва застосунку — **Taskly** за прямим проханням власника від 13.09.2026.
Використовуй Taskly у всьому інтерфейсі, метаданих, PWA, сповіщеннях та
експортованих файлах. Taison — ім’я власника й колишня назва застосунку.
Чинна адреса `taison-delta.vercel.app` і створена раніше тека Google Диска
мають власні ідентифікатори; зберігай доступ до наявних файлів.

## Команди

| Що | Команда |
|---|---|
| Запуск локально | `npm run dev` (потрібен `.env.local`, шаблон — `.env.example`) |
| Типи | `npm run typecheck` |
| Модульні тести | `npm test` · один файл: `npx vitest run src/lib/format.test.ts` |
| Збірка | `npm run build` |
| Перевірки схеми | `npm run test:sql` — одноразовий PostgreSQL 16; шлях до бінарників за замовчуванням лінуксовий, на Mac задай `TAISON_PGBIN` |

`npm run lint` не налаштовано: конфігурації ESLint у репозиторії немає.

CI («Перевірки», `.github/workflows/ci.yml`) на кожен пуш ганяє типи, тести й
збірку з підставними змінними. `test:sql` у CI не входить — запускай його сам,
коли чіпаєш `supabase/`.

## Як влаштовано

- **Next.js 15 (App Router) + React 19 + Tailwind.** Сторінки в `src/app/`,
  спільний інтерфейс у `src/components/ui.tsx`.
- **Зміни даних — server actions у `src/app/actions.ts`.** Користувача бере
  `client()`, після запису — `revalidatePath` для зачеплених сторінок.
- **Supabase.** Клієнти в `src/lib/supabase/`: `server.ts` (сесія),
  `client.ts` (браузер), `admin.ts` (service_role, обходить RLS — приймання
  сканів, крон, токени Google, push; у `actions.ts` один виклик), `scoped.ts`
  (адмін-клієнт, звужений до одного користувача, для резервної копії).
  Кожен запит через `admin.ts` фільтруй за `user_id` сам — база цього вже не
  зробить.
- **Доступ закрито на рівні бази.** У кожній таблиці є `user_id` і політика
  RLS `user_id = auth.uid()`.
- **Гроші — цілими центами** (`amount_cents`), валюта EUR. Розбір і показ суми —
  лише через `src/lib/format.ts`.
- **AI — один контракт у `src/lib/ai/`.** Рушій обирає `AI_PROVIDER`
  (`claude | gemini | openrouter`), схеми відповіді описано в zod один раз.
  Решта коду про рушій не знає — так і має лишатися.
- **Доступ без входу** — список `PUBLIC_PREFIXES` у `src/middleware.ts`.
  Новий маршрут для крона чи Швидкої команди додавай туди й перевіряй
  заголовок `Authorization` у самому маршруті.
- **Офлайн навмисно не кешує дані** (`public/sw.js`): застарілий баланс гірший
  за відсутній.
- **`ios/`** — пробний SwiftUI-скелет, не заміна веб-версії.

## Правила змін

- **Схема.** `supabase/schema.sql` мусить лишатися ідемпотентним: його
  накочують поверх живої бази. Нова колонка — `add column if not exists`,
  політика — `drop policy if exists` + `create policy`. Нова таблиця — одразу
  з `user_id`, RLS і перевірками ізоляції в `supabase/tests.sql`.
- **Схему в Supabase накочує власник вручну** (SQL Editor). Якщо зміна її
  потребує, скажи про це в PR і в підсумку для власника.
- **Нова змінна оточення** → рядок із коментарем у `.env.example` і крок у
  `docs/SETUP.md` (або `docs/GOOGLE.md` / `docs/NOTIFICATIONS.md`). Без неї
  застосунок має показати зрозумілу помилку, а не падати.
- **Логіку покривай тестами** поруч із кодом: `src/**/*.test.ts`.
- **Мова.** Інтерфейс, коментарі, коміти й описи PR — українською.
  Коментар пояснює *чому*, а не *що*.

## Робочий процес

1. Гілка від `main` (`claude/<тема>`).
2. Перед пушем: `npm run typecheck && npm test && npm run build`.
3. PR із розділами «Що всередині» і «Перевірка»; окремо — що має зробити
   власник (змінні у Vercel, накотити схему).
4. Після зелених «Перевірок» — злиття в `main`. Vercel сам публікує `main`;
   гілки отримують preview-адресу.
