# Google Диск: вход и синхронизация

После этой настройки: входишь в приложение кнопкой «Увійти через Google»,
и все сканы сами ложатся в папку `Taison` на твоём Google Диске. Приложение
Google Drive на Маке подтянет их на компьютер — это уже без нашего участия.

Что получится на Диске:

```
Taison/
├── Чеки/
│   └── 2026/
│       └── 2026-09-08 · REWE · 23.47 EUR.pdf
├── Документи/
│   ├── Finanzamt/
│   │   ├── 2026-03-15 · Finanzamt · Рішення про податок · AZ-2025-4471-B.pdf
│   │   └── 2026-03-15 · Finanzamt · Рішення про податок · AZ-2025-4471-B.txt
│   └── Jobcenter/
└── Резервні копії/
    └── taison-2026-09-08-14-30-00.xlsx
```

## Шаг 1. Проект в Google Cloud

1. [console.cloud.google.com](https://console.cloud.google.com) → вверху выбор
   проекта → **New Project** → имя `Taison` → **Create**.
2. Убедись, что вверху выбран именно этот проект.

## Шаг 2. Включи Drive API

**APIs & Services → Library** → найди **Google Drive API** → **Enable**.

Без этого шага всё остальное настроится, но загрузка файлов будет падать.

## Шаг 3. Экран согласия

**APIs & Services → OAuth consent screen**:

1. User Type: **External** → Create
2. App name: `Taison`, support email — твой, developer contact — твой → Save
3. **Scopes** → **Add or remove scopes** → в фильтре найди
   `.../auth/drive.file` → отметь → Update → Save

   Бери именно `drive.file`. Он даёт доступ **только к тем файлам, которые
   создало само приложение**, и относится к несенситивным — поэтому Google
   не требует проверки приложения. Более широкие `drive` или `drive.readonly`
   потянули бы за собой проверку и, возможно, платный аудит безопасности.

4. ⚠️ **Вернись на страницу OAuth consent screen и нажми «Publish app» →
   «Confirm».** Статус должен стать **In production**.

   Это не косметика. Пока статус **Testing**, Google **отзывает refresh-токен
   через 7 дней** — синхронизация будет отваливаться каждую неделю, и ты
   будешь думать, что приложение сломано. С несенситивным `drive.file`
   публикация в production никакой проверки не требует.

## Шаг 4. Учётные данные

**APIs & Services → Credentials → Create Credentials → OAuth client ID**:

- Application type: **Web application**
- Name: `Taison web`
- **Authorized redirect URIs** → Add URI:

  ```
  https://ТВОЙ-ПРОЕКТ.supabase.co/auth/v1/callback
  ```

  Точный адрес возьми в Supabase → **Authentication → Providers → Google**,
  он там показан готовой строкой. Вставляй ровно его.

- **Create** → скопируй **Client ID** и **Client secret**.

## Шаг 5. Подключи к Supabase

**Supabase → Authentication → Providers → Google**:

- Enable Sign in with Google — включить
- Client ID и Client Secret — вставить
- Save

## Шаг 6. Переменные в Vercel

Приложению нужны те же значения отдельно — Supabase токен Google не обновляет,
это приходится делать самим.

```
GOOGLE_CLIENT_ID       = (из шага 4)
GOOGLE_CLIENT_SECRET   = (из шага 4)
TOKEN_ENCRYPTION_KEY   = (см. ниже)
```

Ключ шифрования сгенерируй в Терминале:

```bash
openssl rand -hex 32
```

Им шифруется refresh-токен перед записью в базу: если дамп базы куда-то
утечёт, без этого ключа он бесполезен. **Потеряешь ключ — просто подключишь
Диск заново**, ничего страшного, но старые токены станут нечитаемы.

После добавления переменных — **Redeploy**.

## Первый вход

1. Открой приложение → **Увійти через Google**
2. Выбери аккаунт
3. Google покажет экран «Google hasn't verified this app» —
   **Advanced → Go to Taison (unsafe)**.

   Это нормально для приложения, которым пользуешься ты один: проверку
   проходят те, кто раздаёт приложение публично. Надпись пугающая, но
   доступ ты даёшь своему же приложению и только к папке, которую оно
   само создаст. Убрать надпись можно через brand verification, но ради
   личного приложения это лишняя возня.

4. Дай доступ → вернёшься в приложение уже внутри
5. **Налаштування** → **Створити теки** — папка `Taison` появится на Диске

## Если что-то не работает

| Симптом | Причина |
|---|---|
| `redirect_uri_mismatch` | Адрес в шаге 4 не совпадает с тем, что показывает Supabase. Частая причина — лишний слеш в конце. |
| «Синхронізацію не налаштовано» в настройках | В Vercel нет `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` или `TOKEN_ENCRYPTION_KEY`. Добавь и сделай Redeploy. |
| «Google не повернув refresh-токен» | Согласие уже давалось раньше. Зайди на [myaccount.google.com/permissions](https://myaccount.google.com/permissions), убери доступ Taison и войди заново. |
| Через неделю перестало синхронизироваться | Экран согласия остался в статусе **Testing**. Вернись к шагу 3, пункт 4. |
| Файлы не появляются на Маке | Установи Google Drive для компьютера и включи синхронизацию папки. |
| Загрузка падает с 403 | Не включён Drive API — шаг 2. |

## Что с iCloud

Он больше не нужен. Приложение само создаёт папки и раскладывает файлы —
Быстрые команды для этого не требуются.

Инструкция `docs/SHORTCUT.md` остаётся на случай, если захочется сканировать
родным сканером iOS с автообрезкой: скан всё так же уйдёт в приложение, а
оттуда — на Google Диск. Сохранение в iCloud в той команде можно просто
удалить, оставив только отправку в приложение.
